# Contributing

Thank you for your interest in contributing.

This project is specification-first. The goal is to create stable, evidence-based standards before producing production implementations.

## Guiding Principles

- Respect the project's governance.
- Favor evidence over opinion.
- Keep discussions technical and objective.
- Avoid introducing implementation-specific assumptions into specifications.
- Validate proposals through reference implementations whenever practical.

## Governance

Changes to the project's architecture and specifications are managed through:

- Architecture Decision Records (ADRs)
- Requests for Comments (RFCs)

Major architectural changes should begin as an ADR or RFC rather than a pull request.

## Pull Requests

Before submitting a pull request:

- Ensure the change aligns with an accepted ADR or RFC.
- Include rationale for the change.
- Update documentation where appropriate.
- Keep changes focused and reviewable.

## Code of Conduct

Be respectful, professional, and evidence-driven.

Disagreements should be resolved through technical discussion, experimentation, and documented architectural decisions.

## Project Philosophy

The project exists to define open specifications and validate them through reference implementations.

Implementations serve the specifications.

The specifications do not exist to justify implementations.
